# 2026-Coursework



\# Адаптивная многокритериальная фильтрация в структурированных каталогах с неоднородными параметрами



Прототип системы нормализации и многокритериального поиска по каталогу промышленных вентиляторов.





\### Как запускать



Файлы должны быть в одной папке, например:



VentSearch/

├── ventsearch.exe                  # исполняемый файл

├── ventsearch\_massive\_sorted.csv   # основной каталог

└── ventsearch\_extended.csv         # расширенный каталог





\## Обзор



Реальные CSV-каталоги промышленного оборудования страдают от низкого качества данных:

разнородные единицы измерения (Вт / кВт), инвертированные диапазоны, мусорные значения,

объединённые столбцы. Традиционный подход — удаление дефектных записей — приводит к потере

информации.



Данный прототип реализует двухэтапную систему:

1\. \*\*Нормализация:\*\* очистка, парсинг, приведение к каноническому виду, оценка достоверности каждой записи.

2\. \*\*Многокритериальный поиск:\*\* гибридная индексная архитектура (Bloom-фильтр + хеш-таблица + красно-чёрное дерево) для быстрой фильтрации.



Основные характеристики тестового каталога:

\- 23 883 записи (расширенная версия: 51 546 записей)

\- 6 типов промышленных вентиляторов (ВО, ВЦ, ВКОП, ВР, Ц)

\- 10 полей в исходном CSV, включая диапазоны производительности и давления







\## Возможности



\- \*\*Автоматическая очистка CSV:\*\* удаление BOM, неразрывных пробелов, унификация тире, замена десятичной запятой.

\- \*\*Разбор диапазонов:\*\* поддержка ASCII-дефиса, en-dash и em-dash как разделителей.

\- \*\*Нормализация единиц:\*\* автоматическое определение Вт/кВт через физическую модель и коэффициент согласованности r.

\- \*\*Система статусов:\*\* каждая запись получает метку CORRECT / CORRECTED / NEEDS\_CHECK / ERROR.

\- \*\*Прозрачный вывод:\*\* нормализованный CSV сохраняется с метаданными и кодами ошибок для трассировки.

\- \*\*Гибридный поиск:\*\* Bloom-фильтр для быстрой отсечки несуществующих типов, хеш-таблица для поиска по типу, multimap для поиска по диапазону производительности.

\- \*\*Кроссплатформенное тестирование:\*\* бенчмарк на 8 устройствах (Intel, AMD, ARM) с анализом корреляции ускорения и аппаратных характеристик.







\## Математическая модель (кратко)



\*\*Каноническое представление вентилятора:\*\*

Fan = (Q\_min, Q\_max, P\_min, P\_max, N\_y, D)



\*\*Композиция преобразования:\*\*

f = f\_validate ∘ f\_normalize ∘ f\_parse ∘ f\_clean



\*\*Система предикатов:\*\*

π₁ ≡ Q\_min ≤ Q\_max

π₂ ≡ P\_min ≤ P\_max

π₃ ≡ Q\_min > 0 ∧ Q\_max > 0

π₄ ≡ P\_min > 0 ∧ P\_max > 0

π₅ ≡ N\_y > 0



\*\*Коэффициент согласованности (физическая модель):\*\*

r(Fan) = N\_y / N\_гидр,  где N\_гидр = (Q̄ · P̄) / 3600



Эмпирические границы: r ∈ \[1.5, 10] — типичный диапазон, r ∈ \[0.5, 100] — жёсткие границы допустимости.



Подробнее: см. Главу 2 курсовой работы.







\## Архитектура и алгоритмы



\### Pipeline обработки

сырая строка → f\_clean → f\_parse → f\_normalize → f\_validate → Fan + статус



\### Гибридная архитектура поиска

Запрос:

├── Тип задан?

│   ├── Да → Bloom-фильтр (O(k)) → точно нет? → пустой результат

│   │      └── возможно да → хеш-таблица по типу (O(1)) → проверка предикатов

│   └── Нет → multimap по Q\_min (O(log n + m)) → проверка предикатов
